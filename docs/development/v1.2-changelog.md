# v1.2 Changelog

v1.2 focused on production polish: installability, observability of
notifications, faster scans, and a real advanced-filtering UX.

## Highlights

| Theme | What shipped |
|---|---|
| **Installability** | PWA manifest, hand-rolled service worker, install button, offline page |
| **Web Push** | VAPID-based push notifications integrated into the existing notification fan-out |
| **Notification history** | Full audit log page + retry button for failed sends |
| **Advanced filtering** | 8-dimension filter panel with URL sync + savable presets |
| **Performance** | DB indexes, batched concurrent scan, parallel notification fan-out, pagination totals |
| **DX** | `DATABASE_PATH` actually honored end-to-end |

### Notification history

- Page: `pages/notifications.vue`
- Detail modal: `components/NotificationDetailModal.vue`
- API:
  - `GET /api/notifications` (paginated + filtered list)
  - `GET /api/notifications/:id` (detail)

### Advanced filtering

- Composable: `composables/useFilterState.ts` — single source of truth,
  URL ↔ criteria two-way sync, chip rendering, deep-watch
- Component: `components/FilterPanel.vue` — collapsible panel with chip
  list and tag editor
- Page refactor: `pages/domains/index.vue` — kept status tabs as quick
  shortcuts, added "我的筛选 / My filters" dropdown with save / load /
  set-default / delete; auto-applies the default preset on first load
  when URL has no query
- Saved filters API: `server/api/filters/{index.get,index.post,[id].patch,[id].delete}.ts`
- Schema: `savedFilters` table (added in migration `0002`)
- Domains list filtering extended: `tags` (comma-separated AND-match),
  `sslState`, `expiringDays` query parameters; SSL state filter joins
  `ssl_status_latest` only when needed

### Performance & correctness

- `server/utils/tasks.ts` — `runDomainScan` rewritten:
  - Domains processed in batches of 5 in parallel (was: serial with 1s
    sleep between every domain)
  - 1s sleep between batches only
  - Per-domain logic extracted into `processDomain(d)`
  - All four notification channels run via `Promise.allSettled`
  - Errors isolated per domain
- `server/api/domains/index.get.ts` — returns `total` for pagination,
  caps `limit` at 200
- DB indexes added in `server/db/schema.ts` and applied via
  `server/db/migrations/0002_v12_indexes_pwa.sql` for: `domains` (watch_kind,
  priority, is_active, group_name), `domain_status_latest` (status,
  expires_at), `actions` (triggered_at, action_type),
  `notification_events` (domain_id, event_type, status, channel,
  created_at, sent_at), `ssl_status_latest` (days_until_expiry, valid_to),
  `domain_costs` (domain_id, payment_date, cost_type)
- `server/utils/serverchan.ts` — orphan refactor leftover removed
  (compile error potential)
- `server/utils/db.ts` — now reads `process.env.DATABASE_PATH`, default
  `./data/app.db`, auto-creates parent directory
- `drizzle.config.ts` — loads `.env` via inline parser, honors
  `DATABASE_PATH`

## Migration steps for existing installs

```bash
npm install                                 # pulls web-push + types
npx drizzle-kit push                        # applies 0002
npx web-push generate-vapid-keys --json     # only if you want push
# write VAPID_* into .env
docker-compose up -d                        # or: npm run build && npm run preview
```

No data migration is required — `DATABASE_PATH` defaults match existing
installs (`./data/app.db` locally, `/app/data/app.db` in Docker).

## Product positioning

**DomBeacon (域灯)** is a self-hosted domain ops beacon for tracking wanted domain
opportunities, managing owned domain portfolios, monitoring expiration and
SSL risks, and turning domain events into actionable alerts delivered over
Email, Webhook, Server酱 and Web Push.

Designed for:
- Individual domain investors tracking opportunities
- Small teams managing domain portfolios
- Self-hosted setups that don't want a SaaS dependency
- Internal teams tracking company-owned domains

中文：域灯（DomBeacon）是一个自托管的域名机会与资产健康“信标”，统一监控想要的域名、已拥有域名的到期/SSL 风险，事件触发即时多通道提醒。

## Core concepts

### Wanted vs Owned

| Type | Watch for | Triggers |
|---|---|---|
| **Wanted** (想要) | Availability, redemption | Becomes available, enters PENDING_DELETE |
| **Owned** (已拥有) | Expiration, SSL health | <30 days to expiry, SSL invalid/expiring |

### Priority

`HIGH` / `MEDIUM` / `LOW` — controls visual weight and inherits onto created actions.

### Action queue

Actions are the durable "todo list" generated by status changes. States:
`OPEN` → `SNOOZED` / `DISMISSED` / `RESOLVED`.

Action types:

- `WANTED_AVAILABLE` — wanted domain became registrable
- `WANTED_DROPPING` — wanted domain entered pending-delete / redemption
- `OWNED_EXPIRING` — owned domain inside 30-day expiry window
- `SSL_EXPIRING` — owned domain SSL cert expiring (<30 days)
- `SSL_INVALID` — owned domain SSL cert chain invalid
- `SCAN_FAILED` — RDAP scan exception

## Architecture

### Stack

| Layer | Choice |
|---|---|
| Framework | Nuxt 4 (Vue 3 + Nitro) |
| DB | SQLite via Drizzle ORM 0.45 + better-sqlite3 |
| Styling | Tailwind CSS v4 (Morandi tokens in `assets/css/main.css`) |
| i18n | `@nuxtjs/i18n` (zh-CN default, en-US) |
| Scheduling | `node-cron` + DB-backed task locks |
| Email | Nodemailer (SMTP) |
| Web Push | `web-push` (VAPID), hand-rolled service worker |
| RDAP | Direct fetch against ICANN's RDAP bootstrap |

### Data model (current)

| Table | Purpose |
|---|---|
| `domains` | The watch list (watchKind, priority, tags, group) |
| `domainStatusLatest` | Latest RDAP snapshot per domain |
| `domainStatusHistory` | Append-only RDAP history |
| `actions` | Action queue items |
| `notificationRules` | SMTP + email targets + on/off toggles |
| `notificationEvents` | Every send attempt (channel, status, retryOf) |
| `webhookConfigs` | Outbound webhook destinations |
| `serverchanConfigs` | Server酱 SendKey configs |
| `sslStatusLatest` / `sslStatusHistory` | SSL cert snapshots |
| `domainCosts` / `domainBudgets` | Cost-tracking ledger |
| `pushSubscriptions` | Web Push endpoints (v1.2) |
| `savedFilters` | User-saved filter presets (v1.2) |
| `taskLocks` / `taskRuns` | Scheduling primitives |

Indexes are defined in [server/db/schema.ts](../server/db/schema.ts) and
applied via Drizzle migrations under `server/db/migrations/`. v1.2 adds
performance-oriented indexes via `0002_v12_indexes_pwa.sql`.

### Workflow

1. **Hourly scan** processes active domains in batches of 5 in parallel
   (`server/utils/tasks.ts` → `runDomainScan`)
2. RDAP + (for OWNED) SSL probe runs per domain
3. Status diff creates actions when state transitions
4. Notification fan-out to Email/Webhook/Server酱/Push runs as
   `Promise.allSettled` so a single channel failure doesn't block the others
5. Daily summary at 08:00 (`runDailySummary`)
6. Every send attempt is recorded in `notificationEvents` with retry
   linkage via `retryOf`

### PWA

The app ships a hand-rolled service worker (`public/sw.js`) and Web App
Manifest (`public/manifest.webmanifest`):

- Stale-while-revalidate for static assets
- Network-first w/ 3s timeout for whitelisted read-only API GETs
- Auth and mutating requests stay network-only (never cached)
- Navigation falls back to `/offline` when offline
- `push` and `notificationclick` handlers wired to `/actions` deep-link

Details: [pwa-and-push.md](pwa-and-push.md).

## Deployment

### Docker (recommended)

```bash
docker-compose up -d
```

Volumes: `./data:/app/data` (SQLite file lives there).

### Manual

```bash
npm install
npx drizzle-kit push        # creates ./data/app.db
npm run build
npm run preview
```

### Environment variables

```env
PORT=3000
ADMIN_PASSWORD=             # optional; if set, login is required
DATABASE_PATH=./data/app.db # default; relative paths resolved from CWD
BASE_URL=http://localhost:3000

# Web Push (v1.2). Generate with: npx web-push generate-vapid-keys --json
VAPID_PUBLIC_KEY=
VAPID_PRIVATE_KEY=
VAPID_SUBJECT=mailto:admin@example.com
```

Notes:
- `DATABASE_PATH` is honored at runtime (`server/utils/db.ts`) and by
  `drizzle-kit` (which loads `.env` itself via the inline parser in
  `drizzle.config.ts`).
- Parent directory of `DATABASE_PATH` is auto-created on first boot.
